# Recipe Manager

Аддон для Home Assistant, объединяющий импорт рецептов, планирование
питания, список покупок и синхронизацию с GitHub — в одном веб-интерфейсе,
доступном из панели Home Assistant.

Рецепты хранятся локально в контейнере аддона. Наружу уходят только
запросы, которые вы явно инициируете: скачивание субтитров YouTube,
генерация рецепта через Gemini, поиск товара в OpenFoodFacts,
синхронизация с вашим репозиторием GitHub.

---

## Возможности

### Импорт рецептов

- **YouTube Shorts → рецепт.** Вставьте ссылку на Shorts (или обычное
  видео YouTube) — аддон скачает субтитры через `yt-dlp` и сгенерирует
  структурированный рецепт в формате Markdown с YAML front matter
  через Google Gemini.
- **Markdown.** Импорт из `.md` файлов с YAML front matter. Три режима:
  вставка текста, загрузка файла с устройства, загрузка по URL
  (включая GitHub raw-ссылки).
- **Веб-скрейпинг.** Вставьте ссылку на страницу рецепта — извлечём
  название, ингредиенты, шаги и метаданные через `recipe-scrapers`.
- **Ручной ввод.** Полноценный редактор с полями front matter, nutrition
  и структурированными ингредиентами.

### Библиотека рецептов

- **Поиск** по названию, описанию, тегам, курсам, категориям,
  коллекциям и ингредиентам.
- **Detail-view** с разделами: ингредиенты → шаги → порции → пищевая
  ценность → заметки.
- **Скалер порций** с локальным пересчётом количеств.
- **Nutrition ring** — SVG-диаграмма с макросами и блоком Daily RDA
  (прогресс-бары по дневным нормам).
- **Шаги с чекбоксами** — клик на номер помечает шаг выполненным.
- **Избранное, рейтинг (1–5 звёзд), фото** — по клику разворачивается.

### Планировщик питания

- **Недельная сетка** с приёмами пищи: завтрак, обед, полдник, ужин.
- Навигация по неделям, кнопка «Сегодня».
- Добавление рецепта в план: из карточки (📅), из detail-view
  (кнопка «В план»), из модалки планировщика.
- Указание количества порций для каждого приёма.

### Список покупок

- **Чек-лист** с группировкой «Активные / Купленные».
- **Inline-редактирование количества**: кнопки `−` / `+`, поле ввода,
  выпадающий список единиц (шт, кг, г, л, мл, уп, пач).
- **Добавление из рецепта** — кнопка «🛒» рядом с каждым ингредиентом
  в detail-view или «В покупки» в тулбаре (модалка со всеми
  ингредиентами и масштабом порций).
- **Поиск по штрих-коду** — ручной ввод или сканирование камерой.
  Источник данных: OpenFoodFacts.
- **Сканер камерой** с индикацией распознавания. Поддержка
  EAN-13, EAN-8, UPC-A, UPC-E, Code-128, Code-39 и QR-кодов.
  На Android/Chrome — быстрый нативный `BarcodeDetector`,
  на iOS/Firefox — `html5-qrcode`.

### Экспорт и импорт рецепта

- **Экспорт в `.md`** — скачать рецепт одним файлом с YAML front matter.
  Имя файла: `<slug>_<8-символов-id>.md`.
- **Редактирование в Markdown** — прямо в редакторе: откройте Markdown,
  отредактируйте текст, нажмите «Применить». `id` и `created_at`
  сохраняются.

### Синхронизация с GitHub

- **Двусторонняя синхронизация** `recipes.json` с вашим репозиторием.
- **Fine-grained PAT** с правами `Contents: Read and write` — минимум
  необходимого доступа.
- **Два режима pull**: полная замена локальных рецептов или merge
  по `id` (локальные приоритетнее).

## Установка

### Шаг 1. Добавить репозиторий

[![Добавить репозиторий в Home Assistant](https://my.home-assistant.io/badges/supervisor_add_addon_repository.svg)](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https://github.com/ebloved/recipe-manager-addon)

<details>
<summary>Ручные шаги</summary>

1. **Настройки → Аддоны → Магазин аддонов**.
2. **⋮ → Репозитории**.
3. Вставьте `https://github.com/ebloved/recipe-manager-addon`,
   нажмите **Добавить**.
4. Обновите страницу магазина.

</details>

### Шаг 2. Установить

1. В магазине найдите **Recipe Manager** → откройте.
2. Вкладка **Info** → **Установить**.
3. Дождитесь сборки (2–10 минут при первой установке).

### Шаг 3. Настроить

Откройте вкладку **Configuration** и заполните нужные опции.

#### Основные

| Опция | Обязательно | Описание |
|---|---|---|
| `gemini_api_key` | ✅ для генерации | API-ключ Google Gemini. [Получить бесплатно](https://aistudio.google.com/app/apikey). |
| `gemini_models` | | Список моделей через запятую, по порядку попыток. По умолчанию `gemini-3.8-flash,gemini-3.7-flash,gemini-3.6-flash`. |
| `gemini_proxy` | | HTTP(S)-прокси для запросов к Gemini. |
| `sub_langs` | | Языки субтитров для `yt-dlp`. По умолчанию `ru.*`. |
| `cookies_file` | | Путь к `cookies.txt` (для приватных или возрастных видео). Файл — внутри контейнера. |
| `log_level` | | Уровень логов uvicorn. По умолчанию `info`. |

#### GitHub sync

| Опция | Описание |
|---|---|
| `github_repo` | Репозиторий в формате `user/repo`. |
| `github_username` | Имя для сообщений коммитов. |
| `github_token` | Fine-grained PAT с правами `Contents: Read and write` на этот репозиторий. |
| `github_branch` | Ветка. По умолчанию `main`. |
| `github_path` | Путь к файлу в репозитории. По умолчанию `data/recipes.json`. |

**Как создать токен GitHub:** Settings → Developer settings →
Personal access tokens → **Fine-grained tokens** → Generate new token →
Repository access: только ваш репозиторий → Permissions → Repository
permissions → **Contents: Read and write**. Скопируйте токен — он
показывается один раз.

Нажмите **Сохранить** → вкладка **Info** → **Запустить**.

### Шаг 4. Открыть UI

На вкладке **Info** нажмите **Открыть Web UI** — или найдите
**Recipe Manager** в боковом меню Home Assistant.

## Использование

### Импорт из YouTube Shorts

1. Вкладка **YouTube**.
2. Вставьте ссылку на Shorts.
3. **1. Скачать субтитры** — `yt-dlp` подтянет автосубтитры
   (10–60 секунд).
4. **2. Сгенерировать рецепт** — Gemini вернёт структурированный
   Markdown.
5. Проверьте результат и нажмите **Сохранить в рецепты**.

### Импорт Markdown

1. Вкладка **Импорт → Markdown**.
2. Три варианта:
   - **URL** — вставьте прямую ссылку на `.md` (например,
     `raw.githubusercontent.com/...`).
   - **Файл** — выберите `.md` с устройства.
   - **Вставить вручную** — вставьте текст в поле.

Парсер понимает YAML front matter и fallback на секции
`## Ингредиенты` / `## Шаги` в теле.

#### Формат Markdown-файла

~~~markdown
---
title: Борщ с говядиной
description: Наваристый украинский борщ.
tags: [суп, украинская, зима]
courses: [суп, основное]
servings: 4
prep_time: 20
cook_time: 100
time: 120
source_url: https://example.com/borsch
image_url: https://example.com/borsch.jpg
nutrition:
  calories: 250
  protein: 12
  fat: 8
  carbohydrates: 30
ingredients:
  - name: Говядина на кости
    amount: 500
    unit: г
  - name: Свёкла
    amount: 2
    unit: шт
---

## Ингредиенты

- Говядина на кости — 500 г
- Свёкла — 2 шт

## Шаги

1. Залейте говядину холодной водой, доведите до кипения.
2. Варите **1 час 30 минут** на медленном огне.

## Заметки

- Подавать со сметаной.
~~~

### Экспорт и правка рецепта в Markdown

1. Откройте рецепт → **✏️ Правка**.
2. В шапке редактора:
   - **📥 .md** — скачать рецепт как `.md` файл.
   - **📝 Markdown** — открыть текстовое поле с содержимым рецепта.
3. После правки — **Применить**. Поля рецепта перезапишутся, `id`
   и дата создания сохранятся.

### Добавление в план питания

- Из списка: кнопка **📅** в правом верхнем углу карточки рецепта.
- Из рецепта: кнопка **В план** в тулбаре detail-view.
- Из планировщика: клик по ячейке в недельной сетке.

### Работа со списком покупок

**Добавить товар вручную:** вкладка **Покупки**, введите название,
количество и единицу → **Добавить**.

**Добавить из рецепта:** откройте рецепт → кнопка **🛒** рядом
с ингредиентом (одиночное добавление) или **В покупки** в тулбаре
(модалка со всеми ингредиентами и масштабом).

**По штрих-коду:**
1. **📷 По штрих-коду** → введите код вручную или нажмите **📷**.
2. Камера откроется. Наведите на штрих-код. Когда рамка загорится
   зелёным и появится «✓ Распознано», поиск запустится автоматически.
3. Появится карточка товара — укажите количество и нажмите
   **+ В список**.

**Изменить количество в списке:** используйте кнопки `−` / `+`,
поле ввода или выпадающий список единиц.

### Синхронизация с GitHub

1. Вкладка **Синхронизация**.
2. Проверьте статус — должны отобразиться репозиторий, ветка, файл
   и метка «✓ файл найден».
3. **⬇️ Забрать из GitHub** — заменить локальные рецепты файлом
   из репозитория.
4. **⬆️ Отправить в GitHub** — залить текущие рецепты. Файл создастся
   или обновится.

**Совместное использование:** если нужно, чтобы рецепты были у двух
инсталляций, обе настраивают одну и ту же пару `github_repo` +
`github_branch` + `github_path` со своим fine-grained токеном. После
изменений на одной — push; на другой — pull.

## API

Все эндпоинты доступны по пути ingress-панели:
`https://<ваш-HA>/api/hassio_ingress/<token>/`.

| Эндпоинт | Метод | Назначение |
|---|---|---|
| `/api/recipes` | GET | Список рецептов (поддерживает `?q=`). |
| `/api/recipes` | POST | Создать рецепт (Markdown или явные поля). |
| `/api/recipes/{id}` | GET / PATCH / DELETE | Получить / обновить / удалить. |
| `/api/recipes/{id}/export.md` | GET | Скачать рецепт как `.md`. |
| `/api/recipes/{id}/import-md` | PUT | Заменить поля из Markdown. |
| `/api/recipes/import-url` | POST | Импорт `.md` по URL. |
| `/api/scrape` | POST | Скрейпинг рецепта с сайта. |
| `/api/download` | POST | Скачать субтитры YouTube. |
| `/api/generate-recipe` | POST | Сгенерировать рецепт через Gemini. |
| `/api/meal-plan` | GET / POST | Список / создание плана. |
| `/api/meal-plan/{id}` | PATCH / DELETE | Обновить / удалить запись. |
| `/api/shopping` | GET / POST | Список / добавление товара. |
| `/api/shopping/{id}` | PATCH / DELETE | Обновить / удалить. |
| `/api/shopping/{id}/toggle` | POST | Переключить чекбокс. |
| `/api/shopping/checked` | DELETE | Удалить купленные. |
| `/api/shopping/from-recipe` | POST | Добавить ингредиенты из рецепта. |
| `/api/shopping/lookup` | POST | Поиск товара по штрих-коду. |
| `/api/sync/status` | GET | Состояние GitHub-синхронизации. |
| `/api/sync/push` | POST | Залить `recipes.json` в GitHub. |
| `/api/sync/pull` | POST | Забрать `recipes.json` из GitHub. |
| `/api/health` | GET | Проверка работоспособности. |
| `/api/debug/static` | GET | Диагностика раздачи статики. |

## Хранение данных

Все данные хранятся в постоянной папке `/data` контейнера:

| Файл | Что внутри |
|---|---|
| `/data/recipes.json` | Библиотека рецептов. |
| `/data/meal_plan.json` | Записи планировщика. |
| `/data/shopping_list.json` | Список покупок. |

`/data` переживает перезапуски, обновления и переустановки аддона.
Штатные **Резервные копии** Home Assistant включают её автоматически.

## Требования

- Home Assistant OS или Supervised.
- API-ключ Google Gemini для генерации рецептов из YouTube.
- Интернет из контейнера аддона: для скачивания субтитров, вызовов
  Gemini, OpenFoodFacts и GitHub.
- HTTPS-подключение к Home Assistant (для работы камеры в браузере).

## Решение проблем

| Проблема | Что делать |
|---|---|
| `GEMINI_API_KEY not set` | Вкладка Configuration → вставьте ключ → Сохранить → Запустить. |
| Gemini отвечает «все модели недоступны» | Возможно, вы исчерпали бесплатный лимит. Подождите или укажите прокси через `gemini_proxy`. |
| UI возвращает 404 | Убедитесь, что аддон запущен. Проверьте `/api/health`. |
| CSS/JS не подтягиваются после обновления | Обновите страницу с `Ctrl+Shift+R`. Если не помогает — откройте `?v=N` в `index.html` и увеличьте N. |
| Рецепты пропали после обновления | Не должны. Проверьте `/data/recipes.json` внутри контейнера. Восстановите из резервной копии HA, если файла нет. |
| GitHub: неверный токен (401) | Fine-grained токен должен давать `Contents: Read and write` на целевой репозиторий. |
| GitHub: недостаточно прав (403) | Токен создан без нужного scope или без доступа к репозиторию. |
| Камера не открывается на iOS | Нужно HTTPS. Убедитесь, что HA доступен по `https://`, а не по IP. |
| Warning `Option 'catalog_source' does not exist` | Удалите опции из старой версии: Configuration → Сохранить. Если не помогает — переустановите аддон (данные в `/data` сохранятся). |
| Сканер камерой не находит штрих-код | Убедитесь, что достаточно света, штрих-код в фокусе, рамка наведена на код. QR-коды распознаются, но обычно содержат URL, а не GTIN — поиск может не дать результата. |

### Логи аддона

**Настройки → Аддоны → Recipe Manager → вкладка Log**. Ошибки
`yt-dlp`, `httpx`, FastAPI и Gemini отображаются там же.
