# Recipe Manager

Home Assistant add-on для управления рецептами, планирования питания
и покупок. Импорт из YouTube Shorts, Markdown и веб-страниц; генерация
рецептов через LLM; каскадный матчинг ингредиентов; синхронизация
с GitHub.

С версии 3.1 поддерживаются два режима: **сервер** с общей базой
рецептов и **тонкий клиент (BFF)** в Home Assistant — с локальным
кэшем, офлайн-очередью и синхронизацией.

## Что умеет

### Импорт и создание
- **YouTube** — Apify (транскрипт) + LLM → структурированный Markdown
- **Markdown-редактор** — поддерживает ингредиенты вида
  `Название — 500 г (заметка)`; поля front matter, которых нет в новом
  тексте, сохраняют текущие значения
- **Markdown** с YAML front matter (одиночный файл или массовый batch)
- **Веб-страницы** — JSON-LD / microdata
- **Вручную** — встроенный редактор
- **Голосом** — надиктовать текст на телефоне, разобрать локально или через LLM
- **Генерация через LLM** — гибкий каскад: Custom (Groq/Zveno) → OrcaRouter → Gemini → Admin-провайдеры

### Организация
- **Библиотека рецептов** с поиском по названию, тегам, ингредиентам
- **Профили генерации** — ограничения по калориям, времени, ингредиентам
- **Фильтр «🎯 Только под профиль»** — рецепты, которые тебе подходят
- **Бейдж соответствия** на карточке рецепта
- **Аэрогриль-версии — sub-рецепты**: не занимают отдельную карточку
  в общем списке. На основном рецепте есть чип «♨️ аэрогриль»,
  переключение — в деталях через «Духовка / Аэрогриль».
- **Личные версии рецептов**: в деталях можно нажать
  «Клонировать для себя». Копия видна только владельцу и не занимает
  отдельную карточку: на карточке появляется переключатель
  «Общая / Моя». В режиме «Только мои» показываются свои рецепты
  и свои клоны. В Meal Plan и покупки попадает выбранная версия.
  Внизу личной версии есть кнопка «Откат на общую».

### Планирование и покупки
- **Планировщик питания** — недельная сетка с итогами КБЖУ по дню
- **Список покупок** — объединение дубликатов, поиск по штрих-коду
  (OpenFoodFacts), сканер камерой
- **Оценка `active_time` через LLM** — фоновая, если поле ещё не заполнено

### Готовлю сейчас: навигация и озвучка

- Сверху галка **«Показать ассистента»**, по умолчанию выключена.
- Снизу панель: **«Назад» — «Вперёд»**.
- Вторая строка: галка **«Включить озвучку»** и текущий шаг.
- Переключение шага автоматически проигрывает готовый MP3 шага,
  если озвучка включена.
- Простой тап по шагу выделяет его и проигрывает озвучку этого шага
  (при включённой галке «Включить озвучку»). Для гарнира используется
  его собственная озвучка.
- Никакого микрофона, разрешений и play/pause.
- Аудио шагов генерируется фоновым Gemini TTS по одному MP3 на шаг.

### Голосовой ввод рецепта

- В «Добавить → 🎙 Голосом» есть поле для надиктованного текста.
- На телефоне используется штатный speech-to-text клавиатуры:
  аудио никуда не отправляется, в приложение попадает только текст.
- Сначала работает локальный парсер: ищет название, «Ингредиенты:» и
  «Шаги:», разбирает количества и единицы.
- Если структуры не хватило, текст уходит в LLM с жёстким промптом:
  только структурировать сказанное, не выдумывать продукты и шаги.
- По умолчанию открывается редактор с предпросмотром — можно исправить
  ошибки распознавания и только потом сохранить.
- Галочка «Сохранить сразу» создаёт рецепт без предпросмотра.
- После разбора выполняется нормализация и обогащение: привязка
  продуктов и проверка ингредиентов.
- API: `POST /api/voice/recipe-parse`.

### Безопасность входа

В журнал попадают неудачные попытки аутентификации: запросы без сессии,
недействительные токены, превышение лимита попыток входа, ошибки OAuth,
неверные коды подключения устройства и cross-origin попытки. У событий
сохраняются IP и User-Agent; IP показывается в журнале и участвует в поиске.

### Теги для меню

`tags` и `courses` не обязательны для импорта, но для генератора меню они
важны: по ним определяется приём пищи и тип блюда.

- В `tags` добавьте один или несколько: `завтрак`, `обед`, `полдник`, `ужин`.
- В `courses` укажите тип: `основное`, `гарнир`, `салат`, `суп`, `десерт`,
  `выпечка`, `завтрак`.
- Для основных блюд полезны теги:
  - `самостоятельное` — гарнир уже входит в блюдо (курица с овощами,
    мясо с картофелем, паста);
  - `нужен гарнир` — основное без гарнира (котлеты, стейк, рыба).
- Без тегов генератор попробует определить всё по названию и ингредиентам,
  но может ошибиться.

Шаблон: `app/recipe_template.md`.

### Мой прогресс

На главной есть вкладка **«📈 Прогресс»** с карточкой **«Мой прогресс»**: рост, вес,
необязательный целевой вес, BMI и здоровый диапазон веса для роста.

- Исходные данные скрыты после заполнения; изменить или сбросить их можно
  кнопками в Кабинете.
- Журнал веса, график фактического веса, цель и здоровый диапазон.
- Дневник питания «Что я съел» и график питания план/факт.
- Фото меню: локальное OCR текста и оценка калорий/БЖУ через LLM.
- Опциональные поля БЖУ для записей питания.
- Недельный чек-ин: последний вес, изменение, тренд, среднее питание.
- Прогноз веса по калориям, с уточнением по фактическому тренду.
- Будущие даты для веса и питания недоступны.
- BMI и прогноз — ориентиры, не медицинская рекомендация.

### Квиз питания

В модалке управления профилями есть кнопка **«🧭 Подобрать»**. Квиз
из 5 шагов собирает личный профиль: цель, аллергены и исключения,
нелюбимые продукты, время и технику.

- Личных профилей может быть несколько; они видны только владельцу.
- Базовые профили остаются общими.
- «Поддерживать вес» задаёт ориентиры: ≤600 ккал/порция, белок ≥15 г,
  сахар ≤20 г. Это не «без ограничений».
- Аллергены фильтруются по группам и синонимам ингредиентов, но это
  не медицинский справочник: состав и маркировку нужно проверять.

### Генерация меню на неделю

- В Кабинете у админа есть чекбокс **«Генерация меню на неделю (только админам)»**.
  Он включает блок в «✨ Генераторе» и разрешает LLM-генерацию недостающих блюд.
- В «Генераторе» можно выбрать неделю, профиль, приёмы пищи, порции
  и пожелания. Сначала план собирается из рецептов базы, затем для пустых
  слотов генерируются новые рецепты (не больше 10 за запуск).
- Новые рецепты видны в предпросмотре с жёлтой рамкой «Требует одобрения».
  В план они попадают только после кнопки «Одобрить». Отклонённый слот
  остаётся пустым, для него можно отдельно сгенерировать замену.
- Существующие записи плана не перезаписываются — заполняются только пустые
  слоты. План сохраняется в общий семейный Meal Plan.
- При сохранении можно сразу добавить ингредиенты в покупки; количество
  учитывает порции.
- Черновик плана хранится на сервере и переживает перезагрузку страницы.

### LLM-ключи для пользователей

- В Кабинете у формы LLM-провайдеров есть кнопка **«📖 Как получить ключ»**.
- Модалка объясняет простым языком: зачем нужен ключ, что даёт,
  что будет без него, какой провайдер выбрать.
- Пошаговые инструкции для **Gemini**, **OrcaRouter** и **Custom AI**
  со ссылками, примерами URL/моделей и разбором ошибок.
- Раздел «Помощь → Кабинет и LLM-ключи» переписан для людей,
  которые знают о LLM, но не умеют получать ключи.

### Озвучка шагов рецептов

- В админке есть переключатель **«Озвучивание шагов (Gemini TTS)»**
  и дневной лимит запросов.
- Фоновый воркер генерирует **один MP3 на шаг** и складывает файлы
  в `/data/tts`, метаданные — в SQLite (`recipe_step_audio`).
- Кэш по хешу текста шага: изменился шаг — пересчитывается только он.
- Голос Ludo, модели `3.8 Flash Lite TTS` / `3.8 Flash TTS`.
- Дневной лимит считается по успешным запросам к Gemini.
- API: `POST /api/recipes/{id}/step-audio/{index}`,
  `GET /api/recipes/{id}/step-audio`,
  `GET /api/voice/audio/{hash}.mp3`.

### Журнал действий

- В шапке есть отдельная вкладка **«Журнал»** (только для админа)
  с поиском и фильтрами по статусу и типу действия.
- Пишутся изменения, генерации, импорт, настройки, управление
  пользователями и фоновые задачи: кто, что, когда, объект, статус,
  длительность, ошибка и детали запроса.
- Не пишутся просмотры рецептов, meal plan и список покупок — это
  личные действия.
- Для длительных операций (аэрогриль, генерация, YouTube) видны и
  запуск, и итог фоновой задачи с ошибкой, если она упала.
- Вход/выход и отказы доступа.
- Повторные сессии: при возврате с той же cookie после простоя
  (по умолчанию 30 минут) пишется событие `auth.session`
  с причиной и длительностью простоя.
- Детали события открываются в модалке с подсветкой JSON, полным UUID
  и кнопкой копирования.
- Поиск работает по UUID события, актору, действию, объекту, ошибке
  и модели.
- Для ошибок хранятся `error_code`, `error_provider` и `error_model`;
  сообщения переводятся в человекочитаемый вид (например, 429 —
  «слишком много запросов» с указанием модели).
- Секреты, токены и содержимое рецептов в журнал не попадают —
  только имена полей и краткие метаданные.
- Срок хранения настраивается в системных настройках
  (`audit_retention_days`, по умолчанию 90 дней).
- Таблица SQLite: `audit_events`; сессии — `auth_sessions`.
- Таблица журнала адаптируется под ширину экрана: на ПК занимает
  всю доступную ширину, на смартфоне строки превращаются в карточки.
- API: `GET /api/admin/audit`, `GET /api/admin/audit/actions`,
  `GET /api/admin/audit/stats`, `GET /api/admin/audit/{id}`.
- Для OAuth: `auth.login` — первичная аутентификация,
  `auth.session` — первое использование сессии или возврат после
  простоя, `auth.logout` — выход. В деталях есть `session_id`,
  причина, простой, IP и User-Agent.

### Сезонные эффекты

- В системных настройках админа есть **«Визуальный эффект»**:
  `Нет` / `Снег`.
- Снег рисуется на `<canvas>` поверх экрана рецептов: разные размеры,
  скорость, прозрачность и лёгкое покачивание.
- Даже мелкие снежинки — шестилучевые, а не точки.
- На каждой карточке рецепта в правом нижнем углу появляется еловая
  ветка, повторяющая скругление карточки, и два ёлочных шарика поверх
  неё. Украшение рисуется под текстом и не перекрывает название,
  метаданные и кнопки.
- В шапке страницы, во всю ширину, появляется густая еловая гирлянда
  с несколькими оттенками хвои и ёлочными шариками. Она висит
  повторяющимися дугами `\_/  \_/  \_/` и рисуется **за текстом**,
  не увеличивая высоту шапки.
- Слой имеет `pointer-events: none` — клики, скролл и кнопки работают
  как обычно.
- Эффект работает только на вкладке «Рецепты» и останавливается при
  скрытой вкладке/свёрнутом приложении.
- Уважается системная настройка `prefers-reduced-motion: reduce`.
- Настройка: `visual_effect` (`none` / `snow`).
- Позже сюда же можно добавить другие эффекты, но активным будет
  только один.

### Корзина и восстановление

- Обычное удаление — soft delete: рецепт скрывается из основной ленты.
- В фильтре рецептов есть **«🗑 Удалённые»**.
- Админ видит все удалённые, пользователь — только свои.
- Можно **восстановить** рецепт или **удалить навсегда**.
- При окончательном удалении чистится media, если на неё больше нет ссылок.

### Семантическое обогащение

- Встроенный фоновый enricher на админском Gemini-ключе.
- Модели: `gemini-3.5-flash-lite` и `gemini-3.1-flash-lite`
  (15 RPM / 500 RPD каждая).
- Один рецепт — один запрос, без батчей.
- Работает только когда нет активных пользователей и других
  фоновых AI-задач.
- Заполняет только пустые поля: теги, курсы, категории, коллекции,
  кухню, описание и КБЖУ.
- КБЖУ помечается как `ai_estimate` (`nutrition_source`).
- Статус: `GET /api/admin/enricher/status`.

### Изображения рецептов
- Загрузка JPEG/PNG/WebP до 15 МБ из редактора.
- Автоматическая обработка: `thumb` 480×360, `card` 960×720,
  `full` до 1600 px; WebP, без EXIF.
- Файлы лежат в `/data/media/<sha256>/`; в рецепте только URL.
- В сетке — thumb с `loading="lazy"`, в модалке — card,
  `full` — для просмотра/шаринга.
- `/api/admin/backup.zip` включает media; daily-бэкапы пока только
  JSON + SQLite.

### Данные и синхронизация
- **SQLite — источник истины** — рецепты, покупки, пользователи и токены
  хранятся в `/data/rm.sqlite3`; `recipes.json` остаётся снимком для
  импорта/экспорта и бэкапа
- **База продуктов** — локальная, с каскадным матчингом ингредиентов
  (fuzzy → embeddings → LLM-валидация)
- **Резервные копии** — rolling-бэкапы JSON-файлов и `rm.sqlite3`
  в `/data/backups/`
- **Синхронизация с GitHub** — `recipes.json` + `ingredients.json`
  атомарным коммитом (Git Data API)
- **Общая база на сервере** — snapshot/changes API, device-flow,
  shopping-операции и офлайн-кэш в тонком клиенте
- **Standalone embedding endpoint** — OpenAI-совместимый `/v1/embeddings`
  для матчера; подключается через `matcher_external_url`

## Установка как HA add-on

1. **Settings → Add-ons → Add-on Store → ⋮ → Repositories**
2. Добавить `https://github.com/ebloved/Recipe-Manager-addon`
3. Найти **Recipe Manager** → **Install**
4. **Configuration** — указать минимум `gemini_api_key` (или
   `matcher_external_*` для Hermes / другого OpenAI-совместимого endpoint)
5. **Start**

После старта появится панель **Recipe Manager** в левом меню Home Assistant.

## Сервер и тонкий клиент (v3.1)

### Сервер

- Все пользователи видят общую базу рецептов. `owner_id` определяет,
  кто может редактировать и удалять рецепт; администратор может всё.
- Список покупок — персональный для каждого пользователя.
- Скрытые рецепты — персонально для каждого пользователя.
- Публичные ссылки на рецепты и fork в личную библиотеку.
- OAuth-вход, подписанные сессии, device-flow для подключения клиентов.
- API: `/api/v1/health`, `/api/v1/snapshot`, `/api/v1/changes`,
  `/api/v1/recipes`, `/api/v1/shopping/ops`.

### Add-on как тонкий клиент (BFF)

Включается опциями `remote_mode` и `remote_server_url`. Клиент хранит
только кэш и очередь неотправленных изменений:

- pairing через страницу `/device`; device-token шифруется в
  `/data/remote_device_token.enc`, срок действия скользящий — 90 дней;
- если standalone работает в локальной сети, включи
  `remote_allow_private_urls: true` и укажи адрес вида
  `http://10.0.1.22:8199`; флаг разрешает private-адрес только для
  подключения к серверу и не ослабляет SSRF-защиту импорта/LLM;
- snapshot рецептов и своего списка покупок — в `/data/cache.sqlite`;
- офлайн можно читать рецепты и покупки, создавать рецепты, добавлять,
  отмечать и удалять покупки; операции уходят в очередь;
- синхронизация — раз в 60 секунд и вручную кнопкой «Обновить кэш»
  в Кабинете; при недоступном сервере показывается баннер;
- если отправка не удалась, snapshot не перезаписывает локальный кэш.

### Безопасность и обновление

- `rm_session` — подписанная сессия; глобальный auth-guard, CSRF-проверка
  Origin, rate-limit на `/api/auth/*`, SSRF-защита импорта и LLM-endpoint.
- `SECRET_KEY` генерируется per-install в `/data/.secret_key` (0600).
- Публичный `/api/health` отдаёт только `{"status":"ok"}`; модели,
  наличие ключа и размеры данных — в админском `/api/health/details`.
- Перед обновлением сделай бэкап: `/data/rm.sqlite3` входит в ежедневный
  бэкап и `/api/admin/backup.zip`. `/data/cache.sqlite` можно удалить —
  он пересоберётся из snapshot.
- После перехода на подписанные сессии старые `rm_session` недействительны:
  нужен повторный вход.

## Управление LLM (Кабинет)
В личном кабинете (вкладка «Кабинет») можно настроить свои ключи для LLM:
* **Custom AI** — любой OpenAI-совместимый API (Groq, ZvenoAI и др.). Есть кнопка загрузки списка моделей.
* **OrcaRouter** — быстрый роутер с бесплатными моделями.
* **Gemini** — ключ от Google AI Studio.

Порядок работы: Custom → Orca → Gemini → (если ничего не задано) Admin Gemini → Admin Hermes. Без своих ключей доступно 5 бесплатных генераций в день на пользователя на резервных ключах администратора.

## Магазины
Во вкладке **«🏪 Магазины»** каждый пользователь подключает свои магазины:
* **ВкусВилл** — OAuth 2.0 + PKCE, кнопка «Подключить».
* Токены хранятся только на сервере, в SQLite, в зашифрованном виде.
* Кнопка «🛒 Собрать корзину» собирает корзину из активного списка покупок:
  известные SKU добавляются сразу, новые ищутся через MCP и LLM-каскад.

Список покупок хранится в `/data/rm.sqlite3`. При первом запуске старый
`shopping_list.json` импортируется автоматически, а копия JSON сохраняется
в `/data/backups/pre_sqlite_<timestamp>/`.

Персональные LLM-ключи также перенесены в SQLite (`user_llm_configs`) и
шифруются; `users.json` остаётся для профилей и allowlist.

## Нормализация рецептов
В фоне работает нормализатор:
* приводит ингредиенты к стандарту `app/recipe_template.md` (единицы, дубли,
  количества внутри имени, `optional`);
* связывает ингредиенты с продуктами RM через локальный fuzzy-матчер;
* пишет `schema_version`, `normalization_status`, `normalization_issues`.

На карточке рецепта показывается бейдж «✅ норма» или «⚠️ N».
Управление: `RECIPE_NORMALIZER_ENABLED`, `RECIPE_ENRICHER_ENABLED`,
`RECIPE_NORMALIZER_INTERVAL`.

## YouTube (Apify)
Транскрипты получает Apify Actor, поэтому `yt-dlp`, cookies и обход
bot-check не нужны. Настройки:

```env
APIFY_TOKEN=...
APIFY_ACTOR_ID=automationnation/youtube-transcript-scraper
APIFY_STOP_RATIO=0.9
```

- Транскрипты кэшируются в SQLite (`youtube_transcripts`) — повторный
  импорт того же видео не тратит кредиты.
- В Кабинете (админ) есть блок **«📊 Статус Apify»**: расход, лимит,
  прогресс-бар и кнопка «Обновить».
- При достижении 90% лимита импорт скрывается у всех пользователей,
  API отвечает `503`.
- Полностью отключить: `youtube_import_enabled: false`
  (env `FEATURE_YOUTUBE_IMPORT=false`).
- Обложка из YouTube не подставляется: фото добавляется вручную.

## Помощь
В Кабинете есть кнопка **«❓ Помощь»** — модалка с быстрым стартом,
описанием функций, значений иконок и частыми вопросами.

## Готовлю сейчас
Во вкладке рецептов есть фильтр **«🍳 Готовлю сейчас»** и кнопка **«На кухню»**
на карточке/в деталях рецепта. Можно собрать основное блюдо + гарнир:
- объединённый чек-лист ингредиентов;
- шаги основного блюда и гарнира отдельными блоками;
- таймеры из времени в шагах;
- «Отправить в Сегодня» и «Отправить в покупки».

В Кабинете, в карточке пользователя, есть две личные настройки:

- **«Показывать гарнир»** — показывает карточки гарниров в списке рецептов;
- **«Предлагать гарнир»** — предлагает гарнир при добавлении в «На кухню».
  Для блюд с тегом `самостоятельное` не работает.

Настройки хранятся в браузере.

В Meal Plan блюда можно перетаскивать мышью между днями и приёмами пищи.
На тач-устройствах используйте кнопку «↕» на блюде, затем выберите ячейку.

Активная сессия хранится в SQLite (`current_cooking_sessions`) и доступна
с другого устройства.

## Основные опции

Все параметры — в **Configuration** аддона (YAML / UI). Полный список
со `schema` — в [`config.yaml`](config.yaml).

| Опция | Назначение |
|---|---|
| `runtime_mode` | `minimal` / `standard` / `full` — что включено |
| `gemini_api_key` | Gemini: генерация, эмбеддинги, валидация |
| `gemini_models` | Список моделей (fallback в cascade) |
| `vkusvill_client_id` | OAuth-приложение ВкусВилла (client id) |
| `vkusvill_client_secret` | OAuth-приложение ВкусВилла (client secret) |
| `vkusvill_redirect_uri` | Redirect URI, зарегистрированный у ВкусВилла |
| `vkusvill_scopes` | Scopes OAuth ВкусВилла |
| `matcher_external_*` | OpenAI-совместимый endpoint (Hermes, OpenRouter, Ollama…) |
| `local_embedder_enabled` | sentence-transformers на CPU (без сети) |
| `github_*` | Синхронизация рецептов и продуктов с репозиторием |
| `remote_mode` | Включить режим тонкого клиента (BFF) |
| `remote_server_url` | URL сервера Recipe Manager для BFF |
| `remote_allow_private_urls` | Разрешить LAN/private URL сервера для BFF |
| `semantic_enricher_enabled` | Встроенное обогащение рецептов |
| `semantic_enricher_idle_minutes` | Простой перед запуском enricher |
| `tts_enabled` | Фоновая озвучка шагов (в админке) |
| `tts_daily_limit` | Дневной лимит запросов TTS |
| `audit_retention_days` | Срок хранения журнала действий (дней) |
| `visual_effect` | Сезонный эффект на экране рецептов (`none` / `snow`) |
| `generator_*` | Параметры генератора (лимиты, samples, max_tokens) |
| `off_*` | OpenFoodFacts (поиск штрих-кодов) |


## Разработка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
DOWNLOAD_DIR=/tmp/rm_dl DATA_DIR=/tmp/rm_data \
  .venv/bin/uvicorn app.main:app --reload --port 8099
```

Фронтенд — vanilla JS без сборки. Изменения в `app/static/` подхватываются
сразу, cache-busting через `?v=N` в `index.html`.
