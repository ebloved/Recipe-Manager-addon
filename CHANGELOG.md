## [1.2.0] — 2026-10-05

Крупный релиз: модульная переработка бэкенда, планировщик питания,
список покупок со сканером штрих-кодов, синхронизация с GitHub,
редактор Markdown внутри приложения.

### Added

- **Планировщик питания.** Недельная сетка с приёмами пищи
  (завтрак / обед / полдник / ужин). Добавление рецепта в план — из карточки,
  из detail-view или из модалки планировщика. Навигация по неделям,
  кнопка «Сегодня». Хранение в `/data/meal_plan.json`.
- **Список покупок.** Отдельная вкладка с чек-листом, группировкой
  «Активные / Купленные», inline-редактированием количества (`−` / `+` /
  поле ввода / выпадающий список единиц: шт, кг, г, л, мл, уп, пач).
  Хранение в `/data/shopping_list.json`.
- **Добавление рецепта в покупки.** Кнопка «🛒» рядом с каждым ингредиентом
  в detail-view и кнопка «В покупки» в тулбаре (модалка со всеми
  ингредиентами и масштабом порций). Объединение дубликатов по названию.
- **Поиск по штрих-коду** через OpenFoodFacts. Ручной ввод или
  сканирование камерой. В модалке результата — карточка товара с фото,
  брендом, категорией, источником. Добавление в список покупок с указанием
  количества.
- **Сканер камерой.** Использует нативный `BarcodeDetector` в Chromium
  (Android, Chrome Desktop) и `html5-qrcode` в WebKit (iOS Safari, Firefox).
  Поддерживаются EAN-13, EAN-8, UPC-A, UPC-E, Code-128, Code-39 и QR-коды.
  Индикация распознавания: подсказка «Наведите камеру», зелёная вспышка
  рамки, плашка «✓ Распознано: <код>», переключение в режим поиска.
- **Синхронизация с GitHub.** Двусторонняя (pull / push) синхронизация
  файла `recipes.json` с произвольным репозиторием. Настройки:
  `github_repo`, `github_username`, `github_token`, `github_branch`,
  `github_path`. Поддержка fine-grained PAT со scope `Contents: Read and write`.
  Режимы pull: полная замена или merge по `id`.
- **Экспорт рецепта в Markdown.** Кнопка «📥 .md» в редакторе скачивает
  текущий рецепт в виде файла `<slug>_<8-символов-id>.md` с YAML front
  matter и телом (ингредиенты, шаги, заметки).
- **Редактирование рецепта в Markdown.** Кнопка «📝 Markdown» в редакторе
  открывает текстовое поле с текущим содержимым рецепта. После правки —
  кнопка «Применить» парсит Markdown и перезаписывает поля рецепта.
  `id` и `created_at` сохраняются.
- **Публичная проверка кодов «Честного знака»** через
  `mobile.api.crpt.ru/mobile/check` (без авторизации, только с российских
  IP).
- **Endpoint `/api/debug/static`** для диагностики раздачи статики.

### Changed

- **Модульная структура бэкенда.** `main.py` разбит на пакеты:
  - `stores/` — хранилища (recipes, meal_plan, shopping);
  - `services/` — Gemini, yt-dlp, scraper, product_lookup, github_sync, md_export;
  - `routes/` — эндпоинты (recipes, imports, youtube, meal_plan, shopping, sync, misc);
  - `config.py` — все пути и переменные окружения;
  - `helpers.py` — чистые утилиты.
- **Модульная структура фронтенда.** Статический ресурс разбит на:
  - `css/style.css`;
  - `js/{utils,api,state,tabs,youtube,imports,recipes,detail,editor,plan-picker,planner,shopping,sync,app}.js`.
- **Раздача статики** через явный роут `/static/{path}` вместо
  `StaticFiles` mount — исправляет работу под HA ingress.
- **Layout detail-view** — одноколоночный. Порядок блоков:
  ингредиенты → шаги → порции (scaler) → пищевая ценность → заметки.
- **Карточки рецептов** скрывают фрейм фото, если `image_url` отсутствует.
- **Editor** вынесен в отдельный оверлей с фиксированной разметкой,
  добавлены кнопки экспорта и правки Markdown в шапке.

### Removed

- **Интеграция с «Национальным каталогом»** (`catalog_source`,
  `catalog_api_key`). API-ключ выдаётся только юридическим лицам через
  УКЭП, для частного использования недоступен.
- Неиспользуемые модули из `recipe_manager/` (`const.py`, `models.py`,
  `scraper.py`, `storage.py`).
- Устаревшие CSS-классы inline-редактирования количества
  (`.shop-qty`, `.shop-qty-editor`, `.shop-qty-input`).

### Fixed

- Сканер камерой не давал понять, что распознавание произошло —
  добавлена визуальная индикация.
- Кнопка «В покупки» в карточке рецепта не срабатывала из-за порядка
  загрузки скриптов — исправлено event delegation.
- MIME-типы CSS и JS отдавались как `application/json` под HA ingress —
  исправлено явным указанием `media_type` в роуте статики.
- Кэш браузера не подхватывал обновления после пересборки — добавлен
  cache-busting через `?v=N` в `index.html`.

### Upgrade notes

- При обновлении с 1.1.0: удалите опции `catalog_source` и
  `catalog_api_key` из Configuration аддона (Supervisor запишет warning,
  если они останутся в `options.json`). Или удалите и переустановите
  аддон — данные в `/data` сохранятся.
- Существующие рецепты и настройки совместимы, миграция не требуется.

### Dependencies

## [1.1.0] — 2026-10-04

Импорт рецептов из Markdown.

### Added

- **Markdown import** — импорт рецептов из `.md` файлов с YAML front
  matter. Три режима: вставка текста, загрузка файла с устройства,
  загрузка по URL (включая GitHub raw).
- **Эндпоинт** `recipe_manager/import/markdown` — импорт одной строки
  Markdown.
- **Эндпоинт** `recipe_manager/import/markdown_url` — загрузка по ссылке.
- **Парсер** `parse_markdown_recipe()` в `importer.py`. Понимает
  YAML front matter, fallback на разбор секций
  `## Ингредиенты` / `## Шаги`.
- **Расширение `recipes/add`** — принимает необязательное поле
  `markdown_content`. При наличии парсит и мержит с явными полями
  (явные имеют приоритет). Поле `name` стало необязательным.
- **Frontend** — вкладка **Markdown** в диалоге *New Recipe*.

### Changed

- `manifest.json` — добавлена зависимость `python-frontmatter>=1.0.0`.

### Frontend

- Новая вкладка Markdown в диалоге создания рецепта (требует Recipe
  Manager Card v1.1.0+).

## [1.0.0] — 2026-09-15

Первый публичный релиз аддона.

### Added

- **Импорт из YouTube Shorts** через `yt-dlp` + Google Gemini.
- **Структурирование рецепта** в Markdown с YAML front matter через
  промпт по шаблону `recipe_template.md`.
- **Редактор рецептов** в браузере.
- **Библиотека рецептов** с поиском по названию, тегам, ингредиентам.
- **Detail-view** с ингредиентами, шагами, заметками, скалером порций
  и пищевой ценностью (SVG-кольцо + Daily RDA).
- **Поддержка nutrition** в front matter: калории, белки, жиры, углеводы,
  клетчатка, сахар, натрий, холестерин.
- **Storage** в `/data/recipes.json`.
- **Ingress UI** через панель Home Assistant.

### Dependencies

- `fastapi`, `uvicorn`, `yt-dlp`, `httpx`, `aiofiles`.
