## [1.2.5] — 2026-10-05

Пищевая ценность на 1 порцию, добавление рецептов из планировщика.

### Added

- **Добавление рецепта из планировщика.** При клике на «+» в ячейке
  недельной сетки (или на пустой ячейке) открывается модалка с поиском
  по рецептам. Выбираете рецепт → указываете порции → он встаёт на нужный
  день и приём пищи.
- **Кнопка «+» в ячейках планировщика.** Появляется при наведении,
  не мешает просмотру уже добавленных записей.

### Changed

- **Пищевая ценность теперь явно помечена как «на 1 порцию»** в detail-view.
  Это соответствует формату `recipe_template.md` и редактору
  («Пищевая ценность (на порцию)»). Раньше было неясно, к чему относятся
  значения — к порции или ко всему блюду.
- **Формула подсчёта калорий в планировщике исправлена.**
  Было: `nutrition.calories × (planned / recipe.servings)` — то есть
  показывалась доля одной порции от общего количества блюда.
  Стало: `nutrition.calories × planned_servings` — общий калораж приёма
  пищи = per-serving значение × количество запланированных порций.
  Аналогично для Б/Ж/У.
- **Подпись блока RDA в detail-view:** «Дневная норма (на 1 порцию)».

### Fixed

- Итоги дня в планировщике показывали заниженный калораж, если
  в рецепте было указано `servings > 1` (в частом случае — 4 порции).
  Пересчёт теперь корректен.

### Upgrade notes

- Если ранее вы заносили `nutrition` в расчёте «на всё блюдо», а не
  «на 1 порцию» — значения в планировщике теперь будут отличаться.
  Проверьте любой рецепт: в detail-view должно быть «на 1 порцию»,
  а не «на N порций».

## [1.2.4] — 2026-10-05

Устойчивая синхронизация с GitHub, итоги питания в планировщике.

### Added

- **Итоги по дню в планировщике.** Под недельной сеткой добавлена строка
  «🥗 Итого». Для каждого дня показываются суммарные калории от всех
  запланированных блюд, процент от дневной нормы калорий и Б/Ж/У в
  процентах от дневных норм.
- **Endpoint `/api/meal-plan`** теперь возвращает `recipe_nutrition` и
  `recipe_servings` для каждой записи — фронтенд считает итоги без
  дополнительных запросов.
- **`RM.RDA` в `state.js`** — единый источник дневных норм (2000 ккал,
  50 г белка, 65 г жира, 300 г углеводов). Используется в `planner.js`
  и может использоваться в `detail.js`.

### Changed

- **Нормализация `github_repo`.** Поле теперь принимает любой из форматов:
  `owner/repo`, `owner/repo.git`, `https://github.com/owner/repo`,
  `https://github.com/owner/repo/`, `git@github.com:owner/repo.git`.
  Раньше полный URL приводил к `GitHub PUT 404` без понятной причины.
- **`github_sync.py` переработан:**
  - Добавлена функция `_normalize_repo()`.
  - Перед каждым запросом к `/contents/` идёт проверка `_check_repo_access()`
    и `_check_branch()` — ошибки «нет доступа к репозиторию» и «ветка не
    найдена» теперь возвращают понятные сообщения, а не голый `404`.
  - `status()` возвращает `branch_exists`, `private`, `default_branch`.
- **`config.yaml`** — версия поднята до `1.2.4`, из `arch` удалён `armv7`
  (устаревшая архитектура, Supervisors выводит warning).

### Fixed

- `GitHub PUT 404: message: not found` при вводе полного URL в
  `github_repo` — исправлено нормализацией.
- `INFO: POST /api/sync/push HTTP/1.1 404 Not Found` при неправильно
  настроенном токене — теперь бэкенд делает предварительную проверку
  доступа и возвращает внятный текст.

### Upgrade notes

- Если в `github_repo` был указан полный URL — можно оставить, будет
  нормализовано автоматически. Для чистоты рекомендуется заменить на
  `owner/repo`.
- Опции `catalog_source` и `catalog_api_key` из версии 1.1.x нужно
  удалить из Configuration аддона (или переустановить аддон).

## [1.2.0] — 2026-10-05

Крупный релиз: модульная переработка бэкенда, планировщик питания,
список покупок со сканером штрих-кодов, синхронизация с GitHub,
редактор Markdown внутри приложения.

### Added

- **Планировщик питания.** Недельная сетка с приёмами пищи
  (завтрак / обед / полдник / ужин).
- **Список покупок.** Отдельная вкладка с чек-листом, inline-редактор
  количества (`−` / `+` / поле ввода / выпадающий список единиц).
- **Поиск по штрих-коду** через OpenFoodFacts. Ручной ввод или сканирование
  камерой.
- **Сканер камерой.** Нативный `BarcodeDetector` в Chromium,
  `html5-qrcode` в WebKit (iOS Safari, Firefox). Поддержка EAN-13, EAN-8,
  UPC-A, UPC-E, Code-128, Code-39 и QR.
- **Синхронизация с GitHub.** Двусторонняя (pull / push) синхронизация
  файла `recipes.json` с репозиторием.
- **Экспорт рецепта в Markdown.** Кнопка «📥 .md» в редакторе.
- **Редактирование рецепта в Markdown.** Кнопка «📝 Markdown» в редакторе.
- **Endpoint `/api/debug/static`** для диагностики раздачи статики.

### Changed

- **Модульная структура бэкенда.** `main.py` разбит на пакеты:
  `stores/`, `services/`, `routes/`, плюс `config.py` и `helpers.py`.
- **Модульная структура фронтенда.** Один `index.html` + модульные js.
- **Раздача статики** через явный роут `/static/{path}` вместо
  `StaticFiles` mount — исправляет работу под HA ingress.
- **Layout detail-view** — одноколоночный: ингредиенты → шаги → порции →
  пищевая ценность → заметки.
- **Карточки рецептов** скрывают фрейм фото, если `image_url` не задан.

### Removed

- **Интеграция с «Национальным каталогом»** (`catalog_source`,
  `catalog_api_key`). API-ключ выдаётся только юридическим лицам
  через УКЭП.
- Неиспользуемые модули из `recipe_manager/` (`const.py`, `models.py`,
  `scraper.py`, `storage.py`).

### Fixed

- Сканер камерой не давал понять, что распознавание произошло — добавлена
  визуальная индикация.
- Кнопка «В покупки» в карточке рецепта не срабатывала — исправлено
  event delegation.
- MIME-типы CSS и JS отдавались как `application/json` под HA ingress.
- Кэш браузера не подхватывал обновления — добавлен cache-busting
  через `?v=N`.

## [1.1.0] — 2026-10-04

Импорт рецептов из Markdown.

### Added

- **Markdown import** — импорт рецептов из `.md` файлов с YAML front
  matter. Три режима: вставка текста, загрузка файла, загрузка по URL.
- **Парсер** `parse_markdown_recipe()` в `importer.py`.
- **Расширение `recipes/add`** — принимает `markdown_content`.
- **Frontend** — вкладка **Markdown** в диалоге *New Recipe*.

## [1.0.0] — 2026-09-15

Первый публичный релиз аддона.

### Added

- **Импорт из YouTube Shorts** через `yt-dlp` + Google Gemini.
- **Структурирование рецепта** в Markdown с YAML front matter.
- **Редактор рецептов** в браузере.
- **Библиотека рецептов** с поиском.
- **Detail-view** с ингредиентами, шагами, заметками, скалером порций
  и пищевой ценностью (SVG-кольцо + Daily RDA).
- **Storage** в `/data/recipes.json`.
- **Ingress UI** через панель Home Assistant.
